# PyThermoLinkDB v1.10.0

This release adds first-class support for scalar interaction data stored in
`TableInteractionData`. Interaction tables can now be preserved in a
`ModelSource`, exposed through typed source adapters, and built for one or
multiple mixtures with the new `mkidt*` helpers.

The new examples cover the complete workflow: build an interaction ThermoDB
from reference content, convert it to a reusable model source, and query
ordered interaction parameters such as Pitzer `psi` and `zeta` values.

## Interaction Model Sources

`build_interaction_model_source()` converts an interaction
`MixtureThermoDB` into a mixture-compatible model-source fragment while
preserving the underlying `TableInteractionData` objects.

- Build scalar interaction data with
  `build_interaction_thermodb_from_reference()`.
- Validate and optionally save the resulting interaction ThermoDB.
- Convert it with `build_interaction_model_source()`.
- Combine interaction fragments with component, mixture, or constants sources
  through `build_model_source()`.
- Access the original queryable interaction table from
  `model_source.data_source`.

```python
interaction_model_source = build_interaction_model_source(
    interaction_thermodb=built,
)

model_source = build_model_source(
    source=[interaction_model_source],
)

interaction_data = model_source.data_source[
    "chloride-ion|potassium-ion|sodium-ion"
]["psi"]

psi = interaction_data.get(
    "psi",
    "potassium-ion|sodium-ion|chloride-ion",
)
```

Example: `examples/model_source/model-source-interaction-1.py`

## New Interaction Source Makers

### One Interaction Table

`mkidt()` builds an `InteractionDataSourceCore` for one registered interaction
table and one mixture.

- Select the registered table with `name`.
- Resolve the outer mixture identifier with `mixture_key`, `delimiter`, and
  `case`.
- Inspect registered keys with `props` and table symbols with `props_symbols`.
- Check construction with `summary()` and `build_status()`.
- Inspect the raw table with `table()`, `structure()`, and `info()`.
- Query scalar values, complete records, or component-object inputs.

```python
interaction_source = mkidt(
    name="psi",
    components=components,
    model_source=model_source,
    mixture_key="Name",
)

psi = interaction_source.get(
    "psi",
    "potassium-ion|sodium-ion|chloride-ion",
)
```

Example: `examples/mks/mkidt - 1.py`

### Multiple Interaction Tables for One Mixture

`mkidts()` builds an `InteractionDataSourcesCore` containing multiple
interaction sources for one mixture.

- Retain every available table or select registered keys with `extract_list`.
- Inspect selected keys, de-duplicated scalar symbols, and build status.
- Select a singular `InteractionDataSourceCore` with `select()`.
- Use name-prefixed lookup helpers such as `get()`, `interaction_value()`, and
  `interaction_i()`.
- Aggregate one scalar property with `interaction_property()`.
- Filter records by property, participant, and interaction order with
  `select_records()`.
- Preserve explicitly unavailable values with `include_null=True`.

```python
interaction_sources = mkidts(
    components=components,
    model_source=model_source,
    mixture_key="Name",
    extract_list=["psi", "zeta"],
)

zeta = interaction_sources.get(
    name="zeta",
    property_name="zeta",
    mixture="potassium-ion|sodium-ion|chloride-ion",
)
```

Example: `examples/mks/mkidts - 1.py`

### Multiple Interaction Tables for Multiple Mixtures

`mkidtss()` builds interaction source collections for multiple mixtures in one
call.

- Pass each requested component set through `mixture_components`.
- Receive a dictionary keyed by canonical outer mixture identifiers.
- Apply one `extract_list` consistently across all requested mixtures.
- Optionally report incomplete builds with `check_build=True` without dropping
  the constructed mixture entries.
- Query each mixture independently while preserving the order of its stored
  interaction records.

```python
interaction_sources_by_mixture = mkidtss(
    mixture_components=[potassium_components, lithium_components],
    model_source=model_source,
    mixture_key="Name",
    extract_list=["psi", "zeta"],
    check_build=True,
)
```

Example: `examples/mks/mkidtss - 1.py`

## Ordered Interaction Semantics

Interaction data now keeps registration identity separate from record
identity.

- Outer datasource mixture IDs are canonicalized so the same component set
  resolves to one model-source entry.
- Participant order inside a `TableInteractionData` record is preserved and is
  significant during lookup.
- A differently ordered query does not match implicitly.
- Known symmetry can be enabled explicitly with `symmetric_groups`.

```python
value = interaction_source.get(
    "psi",
    "sodium-ion|chloride-ion|potassium-ion",
    symmetric_groups=[(1, 2)],
)
```

This avoids silently changing the meaning of directional or otherwise ordered
binary, ternary, and higher-order interaction parameters.

## Typed Models and Query Facades

The release introduces public types for working with interaction sources:

- `InteractionDataSource` provides a typed result containing the raw
  `TableInteractionData`, its scalar symbols, registered property name,
  canonical mixture name, and component names.
- `InteractionDataSourceCore` adapts one registered interaction table.
- `InteractionDataSourcesCore` manages multiple registered tables for one
  mixture.

The core adapters expose the `TableInteractionData` lookup surface, including:

- `get()`, `require()`, and `has()` for scalar lookups.
- `get_mixture()` and `get_property()` for record collections.
- `i()`, `iis()`, `interaction_i()`, and `interaction_value()` for compact and
  `DataResult`-compatible access.
- `interaction_property()` and `select_records()` for aggregation and
  filtering.
- `get_from_components()` and `get_mixture_from_components()` for
  `Component`-based queries.

## Public API

The following names are available directly from `pyThermoLinkDB`:

- `build_interaction_model_source`
- `mkidt`
- `mkidts`
- `mkidtss`
- `InteractionDataSource`
- `InteractionDataSourceCore`
- `InteractionDataSourcesCore`

## Example Coverage

- `examples/model_source/model-source-interaction-1.py`: creates, validates,
  saves, combines, and queries a reusable interaction model source.
- `examples/mks/mkidt - 1.py`: builds and inspects one registered interaction
  table, including ordered and component-object lookups.
- `examples/mks/mkidts - 1.py`: selects multiple tables for one mixture,
  checks availability, aggregates properties, retains null records, and
  filters interactions.
- `examples/mks/mkidtss - 1.py`: builds interaction sources for potassium and
  lithium mixtures and demonstrates canonical keys with order-sensitive
  queries.

## Highlights

- Scalar interaction tables are preserved end to end in `ModelSource`.
- The `mkidt()` / `mkidts()` / `mkidtss()` family mirrors the established
  single-source, single-mixture, and multi-mixture maker workflows.
- Canonical datasource registration no longer implies canonical interaction
  record order.
- Explicit symmetry groups make permitted permutations clear at each lookup.
- Typed source objects, availability checks, table inspection, aggregation,
  filtering, and component-based lookup are available through the public API.
