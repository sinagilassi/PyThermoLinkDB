# 🚀 PyThermoLinkDB v1.7.0

This release focuses on matrix data source workflows for mixture properties and makes it easier to build, inspect, and query matrix parameters from a `ModelSource`.

## ✨ New Matrix Source Workflows

### 🧮 Single-Mixture Matrix Data Sources

`mkmdt()` now provides a direct way to build a `MatrixDataSourceCore` for one mixture.

- 📦 Build matrix data for a single component set from an existing `ModelSource`
- 🎯 Control which matrix properties are extracted with `extract_list`
- 🧩 Resolve mixture identifiers with `mixture_key`, `delimiter`, and `case`
- 🔎 Inspect build status, available properties, symbols, and selected matrix tables

Example: `examples/mks/mkmdt - 1.py`

### 🧪 Multi-Mixture Matrix Data Sources

`mkmdts()` adds batch creation for multiple mixtures in one call.

- 🗂️ Build a dictionary of `MatrixDataSourceCore` objects keyed by generated mixture IDs
- ✅ Optionally validate each build with `check_build=True`
- 📚 Reuse the same property discovery and selection helpers on each mixture entry
- 🔍 Access each mixture independently using its generated mixture key

Example: `examples/mks/mkmdts - 1.py`

### 🔄 Directional Matrix Access

The matrix examples now show how pair order affects directional access and how to inspect values from both sides of the relationship.

- ⚖️ Compare component orderings when building the same binary matrix source
- 🔁 Query directional values such as `alpha | methanol | ethanol` and `alpha | ethanol | methanol`
- 🧠 Use `ij()` and `matrix_property()` to inspect individual matrix entries
- 🧱 Use `mat()` and `matX()` to build numeric or alphabetic matrix representations

Examples: `examples/mks/mkmdt - 2.py` and `examples/sources/source_2.py`

## 🔎 Runtime Matrix Access Layer

The `Source` runtime layer now has a clear matrix-oriented workflow for inspecting mixture properties at runtime.

### 🧾 Matrix Inspection Helpers

- `get_matrix()` returns the selected matrix data object for a mixture and property
- `matrix_ij()` reads a specific directional matrix entry
- `matrix_property()` resolves matrix values using component names
- `table()` and `structure()` expose the selected table view and matrix structure
- `prop()` returns the underlying matrix property wrapper used by the builders

### 🧰 Matrix Builders

- `mat()` builds matrix output using a mixture name and property name
- `matX()` builds the same output directly from `Component` objects
- `symbol_format='numeric'` and `symbol_format='alphabetic'` are both demonstrated
- `component_key` can be switched to align numeric and alphabetic representations with name- or formula-based identifiers

Example: `examples/sources/source_2.py`

## 📘 Example Coverage

- 📊 `mkmdt - 1.py`: single-mixture matrix data source creation and property access
- 🔁 `mkmdt - 2.py`: order-sensitive matrix lookup and `mat()` / `matX()` comparison
- 🧪 `mkmdts - 1.py`: multi-mixture matrix data source creation
- 🧭 `source_2.py`: runtime matrix access through the `Source` layer

## 🧩 Highlights

- 📌 Matrix source helpers now mirror the existing `mkdt()` / `mkdts()` workflow style
- 🧭 Examples show how to inspect selected tables, matrix structure, and matrix symbols
- 🔗 Public imports expose the matrix builder helpers and `MatrixDataSourceCore`
